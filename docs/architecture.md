# Architecture

Le monolithe reçoit une requête via public/index.php et le runtime Symfony. App\Kernel charge les bundles, configuration et services. Le routeur sélectionne LandingController pour GET/POST /. Le controller construit WaitlistType, qui gère CSRF et validation. Sur POST valide, le limiteur autorise au maximum cinq tentatives par IP sur quinze minutes ; le honeypot écarte les robots simples ; WaitlistRegistration normalise l’email et utilise Doctrine pour insérer WaitlistEntry. L’index unique protège aussi contre deux requêtes concurrentes. Une redirection 303 évite le renvoi du formulaire lors d’un rafraîchissement. Le message reste identique pour un doublon.

Twig génère le HTML et échappe les données. Vite compile CSS, polices et JavaScript dans public/build. Stimulus initialise le contrôleur studio ; les imports Three.js et GSAP sont différés. Le smartphone utilise une géométrie procédurale et un poster SVG original. Aucun modèle ou média externe requis. Le fallback HTML/CSS existe dès le premier rendu. Les ressources GPU, écouteurs, animations et éventuelle vidéo sont libérés à la déconnexion.

PostgreSQL conserve la liste d’attente, les comptes et les empreintes des codes. Le cache local Symfony stocke temporairement les compteurs antispam ; il convient à une instance locale, et sera partagé pour un déploiement multi-instance. Mailpit reçoit les emails en local ; aucun worker ni envoi extérieur. Le serveur PHP intégré est réservé au développement. Avant production : serveur adapté, HTTPS, APP_ENV=prod, secrets réels, politique de données finalisée, protection réseau et sauvegardes.

## Comptes et espace privé — lot 1

`User` dans `app_user` représente un compte : email normalisé unique, mot de passe haché par Symfony, confirmation et date. `UserRepository` est le fournisseur Doctrine de Security et normalise aussi l’identifiant de connexion. Le firewall vérifie connexion, CSRF et limiteur. `UserChecker::checkPostAuth` interdit la connexion avant confirmation, après vérification du mot de passe afin de ne pas révéler le statut avec un mot de passe incorrect. `/studio` exige ROLE_VERIFIED, calculé à partir de la confirmation : une ancienne session non confirmée ne permet pas d’y accéder. L’utilisateur confirme l’email reçu dans Mailpit avant sa première connexion.

`AccountController` orchestre formulaires et réponses, `AccountAccess` crée les comptes, émet les emails et consomme les codes. `AccountToken` stocke uniquement SHA-256 d’un code aléatoire de 32 octets, propriétaire, usage, expiration et consommation. Durées : confirmation 24 h ; récupération 30 min. Consommation transactionnelle avec verrou du compte puis du code ; un reset révoque tous les liens de reset du compte. L’empreinte du mot de passe en session invalide les anciennes sessions après changement.

L’email utilise APP_PUBLIC_URL, indépendante du Host HTTP. Le code voyage dans le fragment du lien, jamais dans la requête GET ou son journal d’accès. Stimulus transfère le fragment dans le formulaire, efface le fragment de l’URL et attend une confirmation POST avec CSRF. Sans JavaScript, copier le code de l’email. Scanner un lien par GET ne le consomme pas. Réponses sensibles privées/non stockables.

Limites : 5 soumissions compte/IP/15 min, 3 émissions demandées/email/15 min avec clé de cache HMAC, login limité par Symfony. Réponses neutres pour les demandes de compte/liens ; pas de garantie de temps de réponse constant. Mailer synchrone sans Messenger. SMTP Mailpit sur le réseau Compose, interface sur 127.0.0.1:8025 ; aucun envoi extérieur. Ne jamais journaliser le contenu des emails ou les codes. Mailpit est une boîte de développement non persistante, pas un service de production.

## Extension progressive
Bibliothèque, générations, connexions sociales, publications et abonnements apparaîtront dans leur lot. BYOK : clé utilisateur chiffrée côté serveur, fournisseur facturant son client directement ; aucun crédit VydFlow ni achat avec une clé de plateforme. Interface fournisseur ciblée au premier adaptateur réel. Transport et worker Messenger à la première tâche asynchrone. Stockage vidéo privé local d’abord, compatible S3 en production après choix de l’infrastructure. Aucun de ces composants futurs n’est créé dans le lot comptes.
